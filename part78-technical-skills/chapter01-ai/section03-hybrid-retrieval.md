# 混合检索与重排：BGE-M3、Milvus 与 BGE-Reranker

> 学习参考，资料核验日期：2026-10-20。流程与数值用于解释机制，练习未执行，不代表实测最佳参数。

## 核心原理：召回与精排解决不同问题

检索系统通常先从大量文档中快速选出候选，再对较少候选作更细的相关性判断。单路稠密检索擅长语义相近的表达，但遇到错误码、型号、专有名词或数字差异时可能漏掉关键证据；词项检索保留这些线索，却未必识别同义问法。混合检索让不同信号互补，效果仍取决于语料、问题类型与候选覆盖，不能保证每次更好。

BGE-M3 支持稠密、稀疏与多向量表示。稠密表示用一个向量概括文本；稀疏表示保留词项及其权重；多向量表示保留更细粒度交互。常说的“BGE-M3 稠密＋稀疏双路”只是选用了其中两路，不代表模型只能产生两种表示，也不意味着已使用 ColBERT 路径。[BGE-M3 官方模型卡](https://huggingface.co/BAAI/bge-m3)

稀疏表示也不是“传统 BM25 的另一个名字”。BGE-M3 的词项权重来自模型，BM25 则基于词频、逆文档频率等统计规则；它们都可提供词法匹配信号，但生成方式和分数分布不同。做实验时应把 BM25 当作独立基线，不凭模型名称认定哪种一定优胜。

## 双路检索：先让候选有资格，再谈排序

可为同一子块保存 `chunk_id`、`dense_vector`、`sparse_vector` 与元数据。在线用同一问题产生两类表示，在相同租户、权限、版本和适用范围约束下分别搜索，获得两份候选列表，再按稳定标识去重和融合。Milvus 的多向量混合检索支持对多个向量字段分别搜索并合并结果。[Milvus Hybrid Search 文档](https://milvus.io/docs/multi-vector-search.md)

若稠密路先过滤权限，稀疏路却没有过滤，融合后仍可能泄露。正确版本与权限应在候选进入模型之前确定，不能当作排序加分项。回取父块时也需再次检查；对时点类问题应按用户指定时点选择版本，不能总是强制“最新”。

以“设备 E102 固件如何升级”为例，稠密路可能找到所有设备升级教程，稀疏路更可能突出 E102。若问“设备升级后无法连接怎么办”，稠密路可能找到“网络重连故障排查”，弥补字面不同。实际可先各取若干候选再融合，候选数与最终上下文数分开设置；示例取值必须经标注题与延迟预算确定。

## WeightedRanker：融合已有分数

Milvus 的 WeightedRanker 聚合多路候选，对分数作适配或归一化，再按各路权重合并排序。它利用的是检索已产生的分数，不会重新阅读问题与文档正文。不同路的原始 IP、L2 或其他分数不能直接混加，需确认归一化开关及距离方向。[Weighted Ranker 官方机制](https://milvus.io/docs/weighted-ranker.md)

例如，假设两路分数已经正确归一化，文档 A 的稠密、稀疏分数为 0.9、0.2，B 为 0.6、0.9。取权重 0.6、0.4，得到 A=0.62、B=0.72。这只是加权思想的算术例子，不是 Milvus 原始分数的通用计算公式；缺失候选的处理也应以所用版本为准。

调大稀疏权重可能帮助错误码，却可能损害同义改写问题。权重和候选数应在代表性验证集上调优，另保留未参与调参的测试题。若分数尺度难稳定，可比较基于排名的融合策略，但仍需要看评估结果；换融合算法不能把两路都没召回的正确片段补出来。

## BGE-Reranker：重新判断问题与候选的关系

BGE 的常规 reranker 把问题和候选文本组成一对，联合输入序列分类模型，得到相关性分数；这是 cross-encoder 的用法。它与分别编码、预先建立向量索引的召回方式不同，通常只用于较少候选。模型卡给出的 `compute_score` 接受 query—passage 对，归一化选项会将输出变换到 0 到 1。[BGE-Reranker 官方模型卡](https://huggingface.co/BAAI/bge-reranker-v2-m3)

所以“融合”和“重排”虽然都改变顺序，计算依据不同：WeightedRanker 重组已有信号，cross-encoder 重新阅读文本对。两者可串联为“双路召回 → 融合去重 → cross-encoder → 上下文装配”，也可在简单任务中只保留前者。更长候选、更多候选和更大重排模型通常增加推理负担，应测实际批量、截断和尾延迟。

## 边界与常见误区

- 相似度、融合分和重排分都不是答案正确概率。sigmoid 后的 0.9 不自动成为“九成正确”，高相关的过期规则仍可能错误。
- 重排只能排序候选，不能修复缺失原文、错误 OCR 或召回遗漏；失败分析应先看正确证据是否进入候选。
- 切换嵌入模型时，即使维度相同，也不能假设旧文档向量与新问题向量兼容；通常需要按版本重新构建索引并灰度切换。
- 截断可能恰好删掉否定词后的例外条款；长文本支持上限不是推荐分块长度，也不是所有下游组件共同的上限。
- 语义重排不能替代产品编号、时间范围及权限的明确规则。出现证据冲突时回到原文与生效范围，不用分数强行裁决。

**版本敏感：**Milvus 文档导航核验时为 v3.0.x，具体部署可能使用 2.x；SDK 的请求类型、字段索引、融合参数与归一化行为应匹配服务端及客户端版本。BGE 模型应记录精确 revision、tokenizer、最大长度和精度，不能仅记录易变的模型别名。本文避免提供可误认为跨版本通用的调用代码。

## 一句话面试回答

BGE-M3 可同时提供稠密语义和稀疏词法信号，Milvus 双路召回后用 WeightedRanker 融合已有分数，再可用 BGE cross-encoder 对问题与候选联合打分；融合与重排不同，相关性分数也不等于答案正确率。

## 实操练习与预期成果（未执行）

1. 用无敏感信息的三十段样例构造三类问题：同义表达、错误码与型号、相似但规则相反。人工标出相关片段及版本。
2. 固定生成步骤，比较稠密、稀疏、双路融合、融合后重排四条链路，保存每路候选 ID、分数、最终顺序与人工相关性标签。
3. 逐一调整候选数、权重与重排长度，只改一个变量；记录候选召回、最终证据覆盖、耗时与成本，不用答案措辞好坏代替检索评估。
4. 添加一个仅高权限可见的旧版本片段，验证每路过滤与父块回取均遵循相同访问规则。
