# 文档解析与父子分块：先保留关系，再建立索引

> 学习参考，资料核验日期：2026-10-20。工具能力随版本变化；下文解析策略是工程设计建议，练习未执行。

## 核心原理：文件里的字不等于完整语义

RAG 解析的目标是获得“可引用的证据单元”，不仅是一个长字符串。相同文字处于标题、正文、图例或脚注时，含义可能不同；表格里的“10”还需要单位、列名、行名与时间。只检查提取字符数会漏掉顺序错误、跨行串列、条件丢失等问题，后续嵌入再强也无法恢复已经被删除的关系。

可把导入分为：识别文件类型与来源；选择原生解析或 OCR；恢复段落、表格、图片等结构；归一化；质量检查；按结构分块；写入原文和索引。Unstructured 的 partitioning 将文档分解为标题、正文、表格等元素，并提供不同格式的解析入口；这证明统一入口仍需格式相关的处理，不能假设所有输入输出完全一致。[官方 Partitioning 文档](https://docs.unstructured.io/open-source/core-functionality/partitioning)

## Word、PPT、Excel 应分别怎么处理

| 输入 | 容易丢失的关系 | 建议保留的证据位置 |
| --- | --- | --- |
| Word | 标题层级、列表、表格单元格、脚注、修订范围 | 章节路径、段落或表格标识；页码可用时补充 |
| PPT | 页内阅读顺序、图与说明、备注、跨页前提 | 幻灯片号、对象或图表位置、备注来源 |
| Excel | 多级表头、合并单元格、单位、公式与显示值 | 工作簿、Sheet、单元格范围、数据期次 |
| 扫描件或截图 | 阅读顺序、OCR置信、数字与符号 | 原图页码、坐标框、识别文本与复核状态 |

**Word：**先按标题及段落恢复章节树，再处理表格。文档不一定有可靠分页信息，换字体或渲染器可能改变页码，所以引用不宜只依赖第几页。页眉页脚和重复水印可以降噪，但包含版本号、密级、适用范围时不能直接删除。对修订、批注和嵌入对象建立明确政策：使用哪个版本、是否收录备注，避免把草稿意见混入正式规则。

**PPT：**对象存储顺序不一定是读者视觉顺序，宜以单页为基础保留标题、文本框、表格与图片对应关系。箭头、颜色、坐标轴和图例常承担关键语义，可补一段可审核的图表描述，同时保存图像来源。讲者备注可增加上下文，但应独立标识；不能默认备注与屏幕正文具有相同发布范围。先尝试原生文本，对纯图片区域再 OCR，避免全文重复识别。

**Excel：**不宜把整个 Sheet 连成“名称 金额 100 200”。应先识别表区域，补全多级表头，逐行形成带字段名的记录，例如“区域=华东，期间=2026Q3，收入=120，单位=万元”。另存结构化表，跨行求和交给查询或计算工具。公式字符串、缓存结果、显示格式是三种信息；读取公式单元格不代表已经重新计算，公式引擎也可能不支持全部函数或外部依赖。[Apache POI 公式计算文档](https://poi.apache.org/components/spreadsheet/eval.html)

## 多源与 OCR：保留原件，允许失败分流

网页、PDF、Office、图片进入统一中间结构时，至少保留 `source_id`、内容哈希、版本、生效时间、权限、解析器版本和定位信息。OCR 输出增加置信或异常标志；对金额、小数点、正负号、日期、专业缩写重点抽样。字符置信高也不能证明表格列关系正确。原生文本层与扫描图混合时需去重，检测空白页、乱码、重复页和异常短文本，把失败文件送待复核队列，禁止静默成功。

版面分析可同时关注文字、表格、图形位置与标题等逻辑角色。Microsoft Document Intelligence 的 Layout 文档给出了这类结构输出能力，但格式支持、坐标、OCR 范围和 API 限制需按所用版本核实。[官方 Layout 文档](https://learn.microsoft.com/en-us/azure/ai-services/document-intelligence/prebuilt/layout?view=doc-intel-4.0.0)

**版本敏感：**该链接使用 v4.0 文档视图，页面包含多个版本说明；不要将 PDF 的 OCR 行为和页码规则直接套用到 Office 输入。云端解析还需在实际项目中确认数据可发送范围、费用与配额，本文不发起任何文件上传。

## 父子块：让检索精细、让回答完整

父子块设计把章节或完整表格作为父块，把较短、语义完整的段落作为子块。子块保存 `parent_id` 并建立检索索引；命中后回取父块或邻近内容，补足定义、前提和例外。它缓解小块上下文不足与大块匹配不精确的矛盾，但会增加存储、映射维护和上下文预算。

例如父块是“退款规则”，子块分别为“七日内可申请”“已使用商品除外”。若只把第一块交给模型，会遗漏例外；回取父块可恢复限制。父块过大时又会混入其他产品规则，应按标题边界或表格边界继续分层，而不是固定把整份文件作为父块。结构感知分块可优先保持完整元素，再对超长元素拆分；这是与直接按字符硬切不同的取舍。[Unstructured Chunking 文档](https://docs.unstructured.io/open-source/core-functionality/chunking)

回取父块仍须校验同一文档版本和权限，子块可访问不意味着任意父内容都可访问。更新、删除时父子映射与向量一起发布或失效，避免命中新子块却读到旧父块。重叠窗口也会制造重复证据，生成前需按来源、位置与内容去重；“召回十块”可能仅覆盖同一段。

## 一句话面试回答

文档导入要保留标题、表格关系、版本与定位信息，按格式选择原生解析或 OCR，再用子块召回、父块补上下文；分块参数应由实际问题评估，不能用统一长度替代质量检查。
